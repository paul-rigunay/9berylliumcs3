## Encapsulation
I can use encapsulation to compile each item's info and the actions that change it into one single box. Parts outside the program cannot touch the data directly, so the changes must go through set rules before it can be made. This keeps the records safe from incorrect inputs.


## Abstraction
I can use abstraction to hide the background math and messy coding and only show simple buttons to the user. This keeps the program really clean and really easy to use. The main system runs commands without showing how the steps work inside.


## Inheritance
I can use inheritance to make a main blueprint for common items, and then extend that blueprint for specific groups. The groups have commonalities such as name tracking and pricing so I just need to write custom rules. This keeps things organized and saves time .


## Polymorphism
I can use polymorphism to run the same exact action on different items, but each item handles it in its own way. Like using one command on cold drinks shows the temp while it shows the expiration date on fresh snacks. It makes my program more flexible when taking care of many items at once.


## Reflection
In my opinion, encapsulation would be the most useful pillar to improve the store inventory system. As most stores rely heavily on accurate stock counts and pricing, I thought that compiling the data with rules suits well and prevents wrong inputs. This makes sure that the stock cannot drop below 0 and prices cannot be edited by the parts outside the program.
